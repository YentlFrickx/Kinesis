# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Kinesis: an offline-capable PWA (React 19 + Vite + TypeScript, no backend) for planning and following bodyweight strength/stretch/mobility sessions. All user data lives in `localStorage`. See `README.md` for the feature list and Cloudflare Pages deploy setup.

## Commands

```bash
npm install
npm run dev        # http://localhost:5173; animation review sheet at /contact.html
npm run lint       # oxlint (config: .oxlintrc.json)
npm test           # vitest run (tests are src/**/*.test.ts only, node environment, no component tests)
npx vitest run src/player/engine.test.ts            # single test file
npx vitest run -t "name fragment"                   # single test by name
npm run build      # tsc -b && vite build (typecheck is part of build)
```

CI (`.github/workflows/deploy.yml`, `preview.yml`) runs lint → test → build on Node 22. Pushes to `main` deploy to production; PRs from this repo get a preview deploy.

## Architecture

- **Routing** (`src/lib/router.ts`): hash-based (`#/session/:id`, `#/play/:id`, `#/library`, `#/history`). `App.tsx` switches on the route; the player renders full-screen without the tab bar. No router library.
- **Static data** (`src/data/`): `exercises.ts` is the exercise library (55 entries); `templates.ts` holds starter sessions; `types.ts` defines `Exercise`, `Session`, `SessionItem`. Exercises are referenced from sessions by `exerciseId` and resolved via `EXERCISE_MAP`.
- **Stores** (`src/store/`): module-level state + `localStorage` persistence + a listener set, consumed in React via `useSyncExternalStore` (see `sessions.ts` for the pattern: `read()` / `commit()`, versioned keys like `rw.sessions.v1`, storage failures fall back to in-memory). Starter sessions are seeded once (`rw.seeded.v1`) and can be restored via `missingStarters`. Other stores: history, goal, milestones, equipment. If you change a persisted shape, bump the version.
- **Player** (`src/player/`): `engine.ts` is pure logic — `buildSteps(session, lookup)` flattens a session into work/rest steps (per-set rests, left/right with a switch step, "get ready" lead-in using the previous item's `restAfterSec` override), plus `estimateSeconds`/`stepMs` (rep steps have infinite duration until the user taps Done). `screens/Player.tsx` drives it with `cues.ts` (beeps/vibration), `voice.ts` + `useVoices.ts` (speech synthesis cues). Keep the engine free of React/browser APIs so it stays unit-testable.
- **Animation** (`src/animation/`): exercises are drawn as stick figures from keyframe poses (joint coordinates in a 200×140 box, floor at y=126). `skeleton.ts` interpolates poses and defines props/gear; `Figure.tsx` renders; `clock.ts` is a single shared ~30fps rAF clock that runs only while figures are subscribed.
- **Screens/components** (`src/screens/`, `src/components/`): Sessions list, Editor, ExerciseBrowser, History, Player, VoiceSettings; Heatmap/GoalRing/Balance are history visualisations.

## Conventions and gotchas

- Adding an exercise: add an entry to `src/data/exercises.ts`, then visually check the animation on `/contact.html` (entry point `src/contact.tsx`, a second Vite page). If it uses equipment, list the kind in `equipment` and every gear kind drawn in `gear` must appear there. `exercises.test.ts` validates the library.
- `vite.config.ts` honours `BASE_PATH` (default `/`); production is served from the domain root, so don't set it in CI.
- PWA/service worker is generated by `vite-plugin-pwa` (`autoUpdate`); precache globs are `**/*.{js,css,html,svg,png,woff2}`.
- UI design is "Calm": tokens (colours, radii, fonts) live at the top of `src/App.css` with light, `prefers-color-scheme` dark, and manual `data-theme` overrides (`src/store/theme.ts`). Fonts are self-hosted Latin subsets (`src/fonts.css`). Use `components/Icon.tsx` for icons (no emoji) and `components/Sheet.tsx` for confirmations and secondary actions (no `window.confirm`). Axe runs in e2e with no exempted rules, so keep text contrast at AA and avoid `opacity` on text.
- localStorage is per-origin, so previews never touch production data.
